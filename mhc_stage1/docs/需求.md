#### 1.1 整体需求（结论性简要概括）

核心是 SimtVF 自动化划分（基于 `T.Parallel`，以 `T.copy` 为边界等）。

- **stage2**：引入 cost model（提升泛化性）

#### 1.2 stage1 需求分析（核心）

完成最基本的 SimtVF 自动划分，全部使用静态规则进行划分，不引入 cost model，保证功能正确性，保证基本泛化性，不涉及 SIMD；不支持的复杂场景 fall back。

几个关键点：

1. 不考虑 SIMD VF。
2. 只处理 `T.Parallel` 作为 SimtVF 最小单元。
3. 纯 scalar 计算先不放入 SIMT（stage2 再考虑引入 cost model 进行决策）。
4. 基于规则对第 2 点生成的 SimtVF 单元进行融合，核心是：
   - 相邻 `T.Parallel` 可融合；
   - 以 `gm <-> ub` 以及 CV 之间的 `T.copy` 为硬边界断开；
   - 融合有数据依赖的 `alloc_fragment` 和 `T.copy(ub <-> fragment)`；
   - 融合 reduce 等白名单 op；
   - 处理跨界 fragment；
   - 处理 `T.serial` 等（详见 3.1 具体规则）。

### 任务 3：stage1 实现方案

#### 3.1 规则集（最重要，核心）

以下规则需要在研究后给出精确版本：

1. **硬边界确定**：SimtVF 融合不能跨硬边界。硬边界为 `T.copy`，包括 `gm <-> ub` 之间的拷贝，以及 `L0C -> UB` 或 `UB -> L1`（即 CV 边界）。
2. **`T.Parallel` 作为 SimtVF 基本单元**：每个 `T.Parallel` 划分为一个基本 SimtVF 单元；如果 `T.Parallel` 内嵌套 `T.serial`，不对 `T.serial` 做处理，原样保留。
3. **相邻 `T.Parallel` 融合**：需要确认是否有其他不能融合的限制；核心仍然是碰到硬边界就断开。
4. **DMA 分析 / 数据流分析**：分析被 `T.Parallel` 使用的 fragment 的数据流，例如相关的 `alloc_fragment` 和 `T.copy(ub <-> fragment)` 也放进 `T.Parallel`。可参考 `/home/dangy/workspace/Private-ascend/mhc/tvm_dataflow_instruction_dag_research.md` 中的 TVM 能力调研，复用数据流分析能力。
5. **跨不同 SimtVF 作用域的 fragment 处理**：如果某个 fragment A 的生命周期同时出现在 2 个 SimtVF 里，理想情况是 fragment 可以复用（见规则 10），但目前后端不支持这种做法。需要进行数据流分析，将该 fragment A 物化为 shared A，在不同的 SimtVF 里重新申请对应的 fragment L，并插入对应的 `shared A <-> fragment L` 拷贝。在 stage1 下一阶段或 stage2 考虑支持寄存器跨 SimtVF 的能力。
6. **线程数选择**：如果 `with T.kernel` 参数中有 `threads`，直接读取；否则先硬编码为 512。对最佳线程数的分析可以放在 stage2。
7. **`T.serial` 处理**：stage1 中，只有在 `T.Parallel` 里的 `T.serial` 才与 `T.Parallel` 一起放进 SimtVF，其他场景先不分析。参考 `/home/dangy/workspace/TileKernels/docs/auto_simtvf_serial_analysis.md` 对 `T.serial` 的分析结论。后续一个思路是，可以分析 `T.serial` 融进 SimtVF 的可行性（如果只是单纯的算法迭代就可以放进去，但如果存在解不开的依赖关系就不放），这个可以在 stage2 或 stage1 第二版进行分析。
8. **`T.reduce`、`T.fill`、`T.clear` 处理**：目前 TVM log 中，如果这些 op 放在 SimtVF 里，会直接把 `T.fill` 翻译为 `T.Parallel`，`T.clear` 翻译为 `T.fill`。在 stage1 也可以把 `T.fill` 和 `T.clear` 同样视为 `T.Parallel` 进行处理，即放进一个 SimtVF 里，可以直接保留为 `T.fill` 的写法，在 LowerTileOp 会自动处理 `T.fill`。
9. **涉及数据类型转换的 DMA copy**：例如 `T.copy(a_shared, a_gm)`，如果 `a_shared` 和 `a_gm` 数据类型不同，在 Ascend 后端必须放在 SimtVF 或 SIMD VF 中进行。这里不考虑 SIMD VF 的话，可以直接把该 `T.copy` 放入 SimtVF 中。  
   
10. **寄存器复用的可能性**：在目前的硬件能力中，支持同一 fragment 在不同 SimtVF 中被调用，类似：
    ```python
    frag = T.alloc_fragment()
    with T.SimtVF():
        # frag 运算
    with T.serial():
        with T.SimtVF():
            # frag 运算
    ```
    目前在另一个后端是通过一个 layout map 来进行寄存器绑定，这个可以放在 stage1 的下一阶段或 stage2 实现。

对上述规则进行补充和修正，最后直接输出正确的规则集。

```python
# 输入
a, b, c = T.alloc_fragment()
T.copy(b_shared, b)
T.copy(c_shared, c)
for i in T.Parallel(N):
    a[i] = b[i] + c[i]
T.copy(a, a_shared)
T.copy(e_shared, e)

    d[i, j] = e[i] + 1
```

```python
# 输出
with T.SimtVF(threads=M):
    a, b, c = T.alloc_fragment()
    T.copy(b_shared, b)
    T.copy(c_shared, c)
    for i in T.Parallel(N):
        a[i] = b[i] + c[i]
    d = T.alloc_fragment()
    for i, j in T.Parallel(N):
        d[i, j] = e[i] + 1
```

##### case 3：`fragment -> shared` 中转

```python
# 输入
a, b, c = T.alloc_fragment()
T.copy(b_shared, b)
T.copy(c_shared, c)
for i in T.Parallel(N):
    a[i] = b[i] + c[i]
T.copy(a, a_shared)
T.copy(a_shared, a)
d = T.alloc_fragment()
for i, j in T.Parallel(N):
    d[i, j] = a[i] + 1
```

这里需要对 `a_shared` 进行分析：如果 `T.copy(a, a_shared)` 和 `T.copy(a_shared, a)` 之前没有其他操作，则可以融合；如果有其他对 `a_shared` 涉及 GM 或 Cube 的 DMA 操作，则断开。

##### case 4：跨 SimtVF 的 fragment

```python
# 输入
as_ = T.alloc_shared()
al = T.alloc_fragment()
T.clear(al)

for i in T.serial():
    for j in T.parallel():
        al[j] += b[j] + c[i, j]
T.copy(al, as_)
```

对于这个场景，有两种写法：

**写法 1**

```python
as_ = T.alloc_shared()
with T.SimtVF():
    al = T.alloc_fragment()
    T.copy(as_, al)
    T.clear(al)
    T.copy(al, as_)
for i in T.serial():
    with T.SimtVF():
        al = T.alloc_fragment()
        T.copy(as_, al)
        for j in T.parallel():
            al[j] += b[j] + c[i, j]
        T.copy(al, as_)
```

**写法 2**

```python
as_ = T.alloc_shared()
with T.SimtVF():
    T.clear(as_)
for i in T.serial():
    with T.SimtVF():
        for j in T.parallel():
            as_[j] += b[j] + c[i, j]
```

推荐写法 1，因为其保持了 fragment 的局部性和数据流清晰性。
